# Examples 02–06: scientific and execution audit

The five folders under `task/` are imported proposals, preserved for further authoring. They currently **do not pass the MMB scientific closed-loop gate**. In particular, their `solution/solve.sh` scripts copy a prepared `answer.json`; their witnesses check selected fields; their verifiers compare the submission to prepared values or a checklist. A successful local comparison therefore establishes JSON compatibility, not an independently reproduced scientific answer. `tests/reference_answer.json` duplicates `solution/answer.json` in each proposal.

| Example | Intended discovery type | Main blocking issue | Required scientific closure |
| --- | --- | --- | --- |
| 02, AuCu/TiO₂ operando catalysis | Competing mechanisms | The coordination numbers, component counts and mechanism labels are transcribed from the cited paper. The raw XAS/MS archives have not been fitted in the witness. | Fetch and verify the raw spectra and time series; independently fit EXAFS and decompose XANES, align states with the product time series, and quantify support for competing active-site models. Generate the answer from that analysis and test adversarial alternatives. |
| 03, perovskite degradation | Experimental design and selection | The prompt specifies nearly every accepted protocol element. The verifier checks presence, ranges and keywords, not whether an experiment separates the mechanisms. The proposed protocol has no measured outcome or calibrated simulation. The Bath transient-current data and Zenodo stress data concern different studies and do not form matched open-circuit/short-circuit stress-recovery arms. | Define the candidate design space and a data-backed discrimination objective (for example, expected information gain with specified noise and cost); compute a reproducible optimum and verify its score against feasible alternatives. |
| 04, MOF gas separation | Inverse design and candidate discovery | The five-row Agent-visible CSV, together with the prompt thresholds, yields the named answer by a direct filter. The verifier checks the copied table entry. The full Zenodo process archive also contains ready-made KPI evaluations, so exposing those files would recreate the same shortcut. | Supply a substantive candidate space, adsorption isotherms and executable validated process models without exposing precomputed KPI evaluations; score independently calculated mixture-separation outcomes and reject lookup-only submissions. |
| 05, CO₂RR scaling boundary | Boundary and counterexample discovery | The answer values and alloy/additive conclusions are supplied by the cited article. The witness does not reconstruct correlations or a boundary from the supporting data. The 6.2 MB supplemental PDF passed its published MD5 check, but its "Raw Data" section presents plots rather than a machine-readable table of the 137 experiments. | Obtain point-level measurements or establish a documented figure-digitization protocol with uncertainty; specify the correlation/regression definition, calculate alloy and film conditions, and verify a quantitatively supported failure boundary with competing explanations. |
| 06, UiO-66 defects | Anomaly explanation and structure identification | Labels and nominal fractions come from source filenames. The original single-stage Dockerfile exposed the sample-to-source mapping; the corrected image copies only renamed CIFs from a separate build stage. A network-enabled Agent may still locate the public source, and no independent CIF geometry/topology analysis generated the reference answer. The upstream structure repository has no explicit reuse licence. | Confirm data-use rights; freeze an opaque, licensed structure set and prevent source lookup at evaluation time; independently count linkers/clusters, estimate fractions, measure spatial correlation and classify topology from coordinates. |

## Cross-cutting checks

- The ZIP contains only a small candidate CSV for Example 04. Other raw inputs are downloaded at Docker build time. These downloads, hashes, data shapes and scientific computations were not exercised in this audit environment.
- A follow-up source check found that Example 03's six Bath download URLs used incorrect file IDs (the original `Fig4a.csv` URL returned HTTP 404). The IDs have been corrected against the Bath archive's file links; this fixes source addressing, not the missing experimental-design oracle.
- Example 06's nine source CIF URLs returned HTTP 200 and matched the recorded Git blob SHA-1 values in a live source check.
- Example 06 now has a structural witness (`solution/witness/structure_metrics.py`): it checks periodic Zr6 connectivity, identifies complete eight-carbon linkers, and constructs cluster-linker quotient graphs. All nine structures passed defect-family/fraction checks; the three named topologies have distinct graph signatures. `answer.json` and the verifier now also score measured fractions, complete-linker counts, and cluster degree statistics for every sample. Full periodic-net equivalence and quantitative spatial-correlation classification remain to be checked.
- Example 04's published PrISMa isotherm and process archives passed their MD5 checks. `authoring/evidence/recompute_kpis.py` independently reconstructs all four process KPIs for 642 converged equimolar simulations and excludes 10 nonconverged cases. The 298 K pure isotherms do not uniformly cover the low-pressure regime and lack full higher-temperature coverage; selecting sufficient Agent-visible inputs and a validated process computation remains open.
- Example 06's GitHub Actions run 43140857090 passed the scientific-image witness, adversarial verifier tests, Harbor lint and Harbor oracle run (reward 1.0). This establishes the current scoped engineering-pilot execution; the licence and full spatial/topological interpretation gates above still apply.
- `environment/tools/` provides small Python inspection scripts and documentation. `environment/skills/` contains README files only. These are not the broad, usable software and sourced, established Agent Skills required for a research-grade MMB environment.
- No real five-expert baseline or independent Agent trial is present. The configured rule now matches the common template: human-hard means all five experts fail within the task's time limit.
- `tests/test.sh` previously fell back to `solution/answer.json` when an Agent answer was absent. That fallback has been removed; a missing submission now receives zero reward through `verify.py`.
- The proposal verifiers use Python `assert`, which can be disabled with `python -O`; they also accept transcribed or directly selected answers. They must be replaced before live evaluation. `analysis` is ignored by reward, as intended.
- Docker and Harbor execution could not be verified here because Docker is unavailable on this host. A passing package/schema check alone cannot satisfy the scientific gate.

## Release gate

For each example, freeze the actual input snapshot and licence, produce `solution/answer.json` by a traceable computation or experiment, derive verifier targets from independently checked evidence, specify units and tolerances, show positive/negative/boundary tests, run the Agent and verifier images through Harbor, and document the five-expert baseline. Keep `solution/`, `tests/` and `authoring/` isolated from Agent access. Until then, these folders are authoring proposals and should not enter a benchmark reward pool.
